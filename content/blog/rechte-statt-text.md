content:
  - type: "paragraph"
    text: "Ein neuer Starttext bringt keine einzige durchgesetzte Regel mit. Wird ein KI-Agent nur mit neuem Text gestartet, hat er alles, was der letzte hatte, plus eine Bitte. Wirksam abgesichert ist ein Agent erst, wenn er mit angepassten Rechten startet: nur die Ordner, nur die Werkzeuge, nur der Schlüssel, den die Aufgabe braucht, und eine Freigabe durch einen Menschen vor allem, was nach außen geht. Das sind Guardrails im eigentlichen Sinn: Sperren statt Bitten."
  - type: "heading"
    text: "Was ein Text kann und was nicht"
  - type: "paragraph"
    text: "Ein Text im Prompt, ob Playbook, Rolle oder Systemanweisung, wirkt auf das, was ein Agent tun will. Er wirkt nicht auf das, was ein Agent tun kann. Steht darin «schreibe nie in den Kundenordner», hält sich ein Agent in den meisten Fällen daran. In den übrigen Fällen entscheidet nicht der Text, sondern ob der Ordner für ihn überhaupt beschreibbar ist."
  - type: "paragraph"
    text: "Das ist kein Mangel einzelner Modelle, sondern die Natur von Text: Er wird gelesen, gewichtet und gegen andere Anweisungen abgewogen. Eine Sperre im System wird nicht abgewogen. Die Sperre greift."

  - type: "heading"
    text: "Was Rechte konkret sind"
  - type: "paragraph"
    text: "Rechte sind im Alltag eines Unternehmens fünf recht handfeste Dinge. Erstens ein eigener Ordner, in dem der Agent lesen oder schreiben darf, und kein anderer. Zweitens eine Liste von Werkzeugen, die ihm zur Verfügung stehen; was nicht auf der Liste steht, existiert für ihn nicht. Drittens ein eigener Schlüssel mit eigenem Budget, damit ein Fehlverhalten begrenzt bleibt und sich einer Aufgabe zuordnen lässt. Viertens ein Protokoll, in dem jede Aktion steht. Fünftens eine Freigabe durch einen Menschen vor allem, was nach außen geht: zum Kunden, zur Zahlung, in eine Veröffentlichung oder in ein Live-System."  # prüfen: Aufzählung gegen die vetted Landing-Page ki-agenten-unternehmen abgleichen (Freigabe vor Wirkung, Kostendeckel, Protokoll)
  - type: "heading"
    text: "Ein Fall: das Werkzeug, das fehlte"
  - type: "paragraph"
    text: "Im eigenen Betrieb gibt es einen Agenten, der Kundeninstallationen betreut. Am 6. November 2026 sollte er eine neue Version der Software freigeben und konnte es nicht, weil es für ihn schlicht kein Werkzeug «Version freigeben» gab. Ein Satz im Prompt wie «alles ist erlaubt» hätte daran nichts geändert. Die Lösung war kein neuer Satz, sondern das fehlende Werkzeug, mit einer Protokollzeile bei jeder Freigabe."  # prüfen: Aufgabe T257, Stand 09.11.2026 12:04: done, Rollensatz in der Rollendatei, Check vorhanden; Formulierung «Lösung war» gegen den Stand beim Go-live prüfen; Freigabe der Geschichte durch Christian
  - type: "paragraph"
    text: "Der Fall zeigt die andere Seite derselben Medaille: Rechte sperren nicht nur, sie ermöglichen auch. Ein Agent ohne passendes Werkzeug ist nicht vorsichtig, sondern blockiert. Wer Rechte statt Text einsetzt, entscheidet bewusst, welches Werkzeug mit welcher Freigabe zu welcher Aufgabe gehört."
  - type: "heading"
    text: "Ein zweiter Fall: wenn der Text stimmt und das Format nicht"
  - type: "paragraph"
    text: "Ein Prüf-Agent lief im Betrieb einmal kurz auf einem anderen Modell mit derselben Anleitung. Das neue Modell schrieb sein Urteil mit Sternchen, der nachgelagerte Parser erwartete es ohne. Aus einer Freigabe wurde «Mensch nötig», wegen eines Formatunterschieds von einer Zeile. Das Beispiel zeigt, warum auch ein gut geschriebener Text keine Absicherung ist: Er verlässt sich auf das, was das Modell gerade daraus macht. Eine Prüfung, die das Format fest abfragt, und ein Test nach jedem Modellwechsel sichern das ab."  # prüfen: Fall steht in der Verlaufsdatei des Entwicklungs-Managers (14.10.2026) als eine von neun leeren Review-Meldungen; die anderen Ursachen waren ein veralteter Basis-Branch und vier echte Stopps.   - type: "heading"
    text: "Warum sich der Mehraufwand lohnt"
  - type: "paragraph"
    text: "Rechte kosten Einrichtung: Ordner zuschneiden, Werkzeuge freigeben, Schlüssel verwalten, Protokolle lesen. Dafür ändert sich die Frage nach einem Vorfall. Statt «Warum hat sich der Agent nicht daran gehalten?» lautet sie «Welches Recht hätte das verhindert?». Die zweite Frage hat eine Antwort, die sich beheben lässt."
  - type: "paragraph"
    text: "Wichtig ist die Verhältnismäßigkeit. Nicht jede Aufgabe braucht einen eigenen Agenten mit eigenem Schlüssel. Für Wissen und Abläufe genügt ein Playbook. Rechte lohnen sich dort, wo ein Fehler nach außen geht oder teuer wird."

  - type: "paragraph"
    text: "Was bedeutet Human in the Loop in diesem Zusammenhang? Dass ein Mensch eine Aktion freigibt, bevor sie Wirkung hat. Die Freigabe ist ein Recht im System, kein Satz im Prompt."
