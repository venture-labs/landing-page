content:
  - type: "paragraph"
    text: "AI agents may send emails on their own once control and approval have been settled beforehand, and for most emails it makes sense not to start there. A staged approach has proven useful: the agent first writes drafts only, a person reads and sends. Only when a narrow kind of email has proven itself over many cases does automatic sending come into question, and for money, contracts and complaints it stays excluded permanently."
  - type: "heading"
    text: "Draft instead of sending: the basic rule"
  - type: "paragraph"
    text: "An agent can read a lot without doing harm. It becomes critical when writing to the outside, because a sent email cannot be taken back. So the basic rule is: reading yes, effect on the outside only with approval. Wherever an agent would send something, a draft is created and a person approves it."  # prüfen: matches the vetted landing page text ki-agenten-unternehmen ("an agent may read a lot, write only with approval"); compare against the running cluster
  - type: "paragraph"
    text: "Approval is not a gesture here. It is the point where a person checks tone, content and commitments. A draft is a proposal, not a finished result, and that holds for well-running agents too."
  - type: "heading"
    text: "Two agents instead of one: separate reading and writing"
  - type: "paragraph"
    text: "An effective safeguard is to split the tasks between two agents. One sorts the mailbox and recognises which email needs a reply and which matter it belongs to. The other writes only the draft for exactly that one email. Whoever reads needs no write permission. Whoever writes needs no access to the whole mailbox, only to what that one reply requires."  # prüfen: concept "a second agent writes drafts only" per the idea "Email replies: a second agent writes drafts only" (04.11., #2, content-ki-cluster/ideen.md); Christian confirms the description matches his concept
  - type: "paragraph"
    text: "In our own operation, such a drafting agent puts its replies into the drafts folder as drafts and never sends itself. Running examples are rejections of unsolicited applications and replies to enquiries about one specific offer. The email is read like any other and sent by hand."  # prüfen: story from our own operation, status 09.11.2026 per idea #2.   - type: "heading"
    text: "Three stages of autonomy"
  - type: "paragraph"
    text: "Stage 1 is the draft: the agent writes, the person reads, edits and sends. Every edit and every unchanged approval shows how reliably the agent works for this kind of email."
  - type: "paragraph"
    text: "Stage 2 is automatic sending for exactly one narrow kind of email, such as the reply to enquiries that always follow the same course. The threshold is a number, not a feeling: in our own case, the agent may only reply automatically after ten of its drafts have been sent by hand. Ten is the threshold for this one case and not a standard for all."  # prüfen: idea "When may the agent send on its own? After ten manual sends" (04.11., #3). Autonomy is not a permanent state, it is earned continuously."  # prüfen: fallback rule per idea #3 ("if I edit often, it stays in stage 1"); check before go-live whether it is built in technically
  - type: "heading"
    text: "What should never be sent automatically"
  - type: "paragraph"
    text: "For money, contracts, complaints and legal questions, a person writes themselves or checks every sentence. This holds even when the agent has long worked reliably in stage 2 for other emails. The reason is simple: the possible damage of a wrong email is greater there than the time saved."
  - type: "paragraph"
    text: "A second limit concerns recipients. Emails to prospects who never had contact are legally a terrain of their own. For advertising by email, strict rules on consent apply, which must be settled before any automation."  # prüfen: legal statement (consent for advertising emails, §7 UWG) verify via WebSearch against an official source before go-live or delete
