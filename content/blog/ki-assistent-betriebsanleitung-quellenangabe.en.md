  - type: "paragraph"
    text: "An AI assistant for operating manuals answers questions about a machine in plain language, for example “What torque applies to this fastening?” It is only useful under three conditions: every answer names the place it comes from, the assistant says “not found” instead of guessing when nothing is written down, and it may read but never change anything. Without these three points, the time saved becomes a risk."
  - type: "heading"
    text: "The problem: the answer is somewhere, but where?"
  - type: "paragraph"
    text: "Operating manuals are long, often several hundred pages, and usually stored as PDFs. Add wiring diagrams, service reports and notes on individual machines. Someone standing at a machine rarely needs a whole manual, only one specific value. An assistant that finds that value in seconds saves search time. It can also do harm if it states a wrong value with great confidence."
  - type: "heading"
    text: "Rule 1: the answer names its source"
  - type: "paragraph"
    text: "Language models write fluently even when they are wrong, so a good-sounding sentence is not enough. Every answer needs a reference to the document, page or section it comes from, ideally one that opens with a click. That lets the technician check within seconds whether the answer really says that, and whether it is the manual for exactly this machine and this version."
  - type: "paragraph"
    text: "This also changes the assistant's role: it is not an oracle but a fast signpost to the right page. For safety-relevant values, the original passage remains authoritative, not the assistant's wording."
  - type: "heading"
    text: "Rule 2: “not found” is a valid answer"
  - type: "paragraph"
    text: "The most dangerous answer an assistant can give is one that sounds plausible and is documented nowhere. A useful assistant therefore answers only from the stored documents. If it finds nothing matching, it says so openly and suggests whom to ask, such as the manufacturer or the colleague with experience on that machine. “I don't know” is not a weakness; it shows that the assistant does not make things up."
  - type: "paragraph"
    text: "An example: someone asks for a value that the manual only gives for a predecessor model. A good assistant does not simply pass the value on but points out that the passage concerns a different model. A poor one takes the number because it fits the question."
  - type: "paragraph"
    text: "Whether an assistant follows this rule can be tested: with test questions whose answers are known, and with questions that deliberately have no answer. Only when both kinds are handled cleanly is it fit for daily use."  # prüfen: Testing logic is written as a general recommendation, not a documented standard or product feature; agree with Christian whether to keep this paragraph or describe the product's actual testing practice
  - type: "heading"
    text: "Rule 3: read yes, change no"
  - type: "paragraph"
    text: "An assistant for operating manuals needs read access to documents and no write permission. It has no reason to delete, overwrite or send anything. Withholding the permission in the first place means less worry about misbehaviour: in the worst case the assistant reads something out wrongly, but it changes no data."
  - type: "paragraph"
    text: "In our own operation the same rule applies to agents: they may read broadly, but write only narrowly and with approval. For checking payments, for example, there is an access that only allows queries."  # prüfen: Own operation, status 04.11.2026 per the idea list “The agent may read everything and write nothing”; Christian confirms the story and the status date, no customer names and no key details
  - type: "paragraph"
    text: "It also means credentials never appear in plain text in an answer. An assistant that simply prints a password would be a data leak with a chat function. So it gets only the permissions its task needs, and secrets stay outside what it can see or output. The protection lies in how permissions are cut, not in trusting the model."  # prüfen: Own operation, status 08.11.2026 per the idea list “Your AI agent must never read out your password”; Christian confirms the statement; the protective check mentioned there is deliberately described only in general terms
  - type: "heading"
    text: "Limits: what an assistant does not replace"
  - type: "paragraph"
    text: "An assistant does not replace a technician. It knows only what is in the documents and nothing about the condition of the specific machine, about modifications, or about what was never written down. It is only as good as the documents it answers from: outdated, duplicated or contradictory documents lead to outdated, duplicated or contradictory answers."
  - type: "paragraph"
    text: "In practice this means every document should be recognisably tied to a machine and a version, with model, year of manufacture or revision. When a new manual is added, the old one should not quietly stay in use. Only then can an assistant tell “applies to this machine” from “applies to a different model”. Skipping this discipline gets only faster confusion, even with the best language model."
  - type: "paragraph"
    text: "In addition, for safety, warranty and approvals a person decides with the original source in hand. The assistant shortens the way there; it does not carry the responsibility."
