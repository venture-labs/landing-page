    text: "An AI playbook is a written guide that tells an AI agent how to do a task: goal, steps, limits and output format. It is text the agent reads before it works, not software."
  - type: "heading"
    text: "When a playbook is enough and when it is not"
  - type: "paragraph"
    text: "A playbook describes the procedure, a role sets the perspective the agent works from, and a skill is a knowledge package added when needed. A playbook is enough as long as the agent only lacks knowledge or a procedure. It is a request, not a lock: what an agent may not do is governed by permissions and approvals."
  - type: "heading"
    text: "Example from our own operation"
  - type: "paragraph"
    text: "In our own operation, agents for recurring tasks each have a playbook of about one page: what the goal is, which steps follow, what must never happen and what the result should look like. When a procedure changes, the text is edited without building anything on the agent itself.   - type: "paragraph"
    text: "A playbook makes sense for tasks that come up often, follow a clear procedure and whose result can be checked quickly: sorting mail, pre-qualifying enquiries, preparing reports in a fixed format. It helps to start with a task someone on the team already knows well. That person's knowledge is written down and tested on real cases."
